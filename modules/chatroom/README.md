# 局域网聊天室

打开扩展选项中的「局域网聊天室」，或在全屏课程助手左下角点击聊天图标，在当前页面展开聊天窗口。联系人与设置的结构统一放在 options.html 中，聊天页直接引用；昵称、隐私和服务器设置自动保存。浏览器无法读取 Windows 用户名或电脑名，因此首次使用会生成设备昵称。

## 连接其他设备

- **在线发现**：双方打开聊天室并点击「刷新发现」。默认使用 LocalSend 的公共信令服务 `wss://public.localsend.org/v1/ws`，也可在选项中设置其他兼容服务。服务器只帮助发现设备和交换连接信息，不接收聊天正文、文件或屏幕内容。该公共服务由第三方运营，不保证长期可用。相同网络出口不代表同一局域网；设备发现成功也不保证可以直连。
- **手动配对**：一方生成邀请并发给对方；对方接收邀请、生成应答；发起方提交应答。双方核对身份指纹。连接码含网络连接信息，只应发给可信的人；此方法不需要公共信令服务。

消息、文件和屏幕均通过浏览器 WebRTC 加密直连，不需要安装 Bridge。本模块不使用 TURN 中继，网络隔离、防火墙或浏览器策略可能阻止连接；不是 LocalSend 原生客户端的文件传输协议实现。

## 使用自己的局域网服务器

安装本地 Bridge 的命令后，点击选项中的「启动本机聊天室服务器」（`bjtuca://chatroom`），或在终端运行 `bjtuca chatroom`。自定义端口可使用 `bjtuca://chatroom?port=1897` 或 `bjtuca chatroom --port=1897`。

该服务独立监听 1897 端口，不修改 Bridge 的 1896 端口及配置，也不依赖浏览器扩展连接。终端会列出本机的连接地址；将同一个 `ws://服务器局域网IP:1897/chatroom` 填入双方的「在线发现服务器」，再刷新发现。服务器所在电脑可能需要允许防火墙访问，退出终端或按 Ctrl+C 即可停止。

服务器只交换设备目录和连接信息，不存储或转发消息正文、文件和屏幕。普通 `ws://` 不加密设备目录及连接信息，仅建议用于可信局域网；内容仍通过经过身份签名校验的 WebRTC 加密直连。

## 聊天与隐私

已连接用户可以进入公共群聊、私聊，或创建群聊。可以为设备备注、请求添加好友、拉黑设备，并设置「仅好友可以联系我」。群邀请可每次确认、直接接受或全部拒绝，也可在拒绝邀请时禁止该发送者后续邀请。退出群聊后不再接收该群消息。

文件需收件人确认才开始传输；支持流式写盘的浏览器可直接选择保存位置，否则内存接收总量限制为 128 MiB。屏幕共享需要主动选择屏幕，并由观看方确认，不包含远程控制。在 app.html 中收起聊天室窗口会停止屏幕共享，但保留连接和文件任务；关闭整个页面才会断开连接，传输中不要关闭页面。

身份、昵称、备注、权限与有界聊天历史保存在本地扩展存储。身份签名可防止其他设备冒用已记录的身份，但不证明昵称或真人身份；首次连接仍需自行核对。
